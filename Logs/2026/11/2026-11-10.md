**Design.** Forcing (`--force`) appends a target after the schedule, which is
wrong for a target that is already scheduled. Both schedulers already honour
a per-row `t_target` (T3.3) and place the row normally. So the new flag
`--set-time NAME@MIN` sets `t_target` on the loaded table:
- `targets_io.parse_time_spec` and `apply_time_overrides`. An unknown name
  is an error, not ignored; the name splits on the last '@'.
- A `time_overrides` argument on both `analyze_targets`, and the flag in both
  `parse_args`.

Because the flag lands in `plan.request.argv`, later regenerates keep it.

**API.** `/api/regenerate` now takes optional `forced` and `times` lists. A
list that is given replaces its flags; an omitted one is kept. So the
Rejections page (which sends only `forced`) and the plan page (only `times`)
never undo each other. A small helper (`_drop_flag`, `_flag_pairs`)
replaced the old inline loop.

- **Apply time changes & regenerate** sends every setting (old plus
