**What I learned from the code** (details in the brain, v0.89):
- The night is a grid of one-minute legal/illegal flags.
- Each block's length comes from a magnitude lookup table plus 7 min. The
  S/N-mode and moon model is dead code.
- Two solves run, with standards placed in fixed slots between them.
- Each priority tier gets a depth-first branch and bound, minimising median
  airmass with a 100000 penalty per dropped target. Earlier tiers come back
  as mandatory but movable.

**The toy night.** I wanted the comparison tab to rest on computed numbers,
not invented ones. `scripts/compare_scheduler_styles_toy.py` re-implements
both rule sets in miniature on six SIM targets. My first design surprised
me: AstroScheduler dropped a P2 target that it could have fitted by moving a
P1 one, after 20,557 calls. That is the search cap, not a toy bug. I did not
want to publish a claim against someone else's code based only on my own
re-implementation. So `scripts/astroscheduler_toy_check.py` runs the real
v1.3.0 solver on real-sky versions of the same targets (RA set so each
transits at the toy time, night clamped to 540 min, standards off). It
agreed to within 1–2 min (sidereal drift) on every block and outcome,
including the capped drop. It also exposed a small bug: the same name listed
twice in `conflicts`.

I then split the toy into two scenarios:
- **main:** the everyday differences. night-planner packs P1 early, so it
  loses the early-setting SIM-D. AstroScheduler places P1 at transit, so
  SIM-D fits. AstroScheduler's Dec +72 limit makes SIM-F unobservable. A
  late riser goes in at airmass 2.02 under night-planner and 1.38 under
  AstroScheduler.
- **cap:** the search limit. I added a witness schedule, which the script
  checks (all minutes legal, no overlaps, cost 4.10 against 100003.03).
